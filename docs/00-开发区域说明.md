## 3. 与计划文档 §3.1 的差异（重要）

计划原文写的是 `src\DsInApex.Engine\ ← C++ 引擎（同步自上游 src/）`。
**实际落地改为独立的 `engine\` 目录、且是整仓库镜像。** 理由：

1. **根 `CMakeLists.txt` 位于仓库根**，不是 `src/` 下。CMake 的 `project()`、
   `add_library`、`add_executable` 全部相对仓库根定位源文件。
2. 引擎除 `src/` 外还依赖 **`shared/`、`third_party/`、`assets/`、根级 `.rc` 资源**，
   只搬 `src/` 会导致 CMake 无法配置。
3. 上游 `CMakeLists.txt` 使用**显式文件列表**（非 `file(GLOB)`），
   意味着新增文件必须改脚本 —— 保持仓库原样才能让上游的脚本改动直接 merge。

**因此 `engine\` = 上游仓库 1:1 镜像**，其 `.git` 被主仓库 `.gitignore` 排除，
作为独立仓库管理，未来通过 `git remote` 直接跟进上游提交。

## 5. 硬约束（不可违背）

1. **许可证 GPL-3.0-or-later**：必须开源、必须随二进制提供源码、
   必须保留原版权声明并标注"已修改"。
   （上游 README 写 MIT 是文档错误，以 `LICENSE` 文件为准。）
2. **`engine\src\` 保持上游原样**，只允许做本地化相关的必要改动，且改动点要集中可数。
3. **构建路径纯英文** —— 本区域即为满足此约束而存在，不得在区内建中文目录。
4. 主仓库 `E:\DsInApex\` 的 `engine\` 已忽略；引擎改动不得隐式混入主仓库历史。
