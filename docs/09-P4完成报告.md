## 3. 本轮踩到的坑（均已修复）

### 3.1 🔴 内核驱动服务不在 `Win32_Service` 里（**本轮最有价值的一条**）

第一版把所有服务都报成 `Stopped`，与 P2 记录的环境（全部 Running）矛盾。

**根因**：`usbip2_ude` / `usbip2_filter` / `HidHide` / `ViGEmBus` **全都是内核驱动服务**，
它们出现在 **`Win32_SystemDriver`**，**不在 `Win32_Service`**（后者只列用户态服务）。
查询返回空集合 → 代码走了「服务键在但查不到实例」的分支 → 误判为 `Stopped`
→ 整个驱动状态从 `Running` 被错降级为 `Installed`。

**修法**：两个 WMI 类都查（内核驱动优先，再退用户态服务）。

**教训**：**"服务"是个含糊的词。** 查 Windows 服务状态前先确认它是 Win32 服务还是内核驱动，
两者的 WMI 类不同，混用会静默返回空结果 —— 而"空结果"很容易被误当成"没在运行"。

### 3.2 PRI249：`Invalid qualifier: 0-X64`

把驱动安装器作为 `<Content>` 加进项目后，构建出现警告：

```
WINAPPSDKGENERATEPROJECTPRIFILE : warning : PRI249: Invalid qualifier: 0-X64
```

**根因**：PRI 资源索引器扫描 `Content` 项，把文件名 `USBip-0.9.8.0-x64.exe` 里的
`-x64` 解析成了资源限定符。

**修法**：改用 `<None Update="Prerequisites\*" CopyToOutputDirectory="PreserveNewest" />` ——
`None` 项不参与 PRI 索引，同时仍会复制到输出。**警告消失，文件照常复制。**

### 3.3 `InfoBar` 也不是 `ContentControl`

`InfoBar` 的正文在 `Message` 属性上。`loc:Localize.Key` 的智能路由对它同样会错塞 ToolTip，
已在 `Localize.ApplyAuto` 补分支。（与 P3 的 `AutoSuggestBox` 同一类问题。）

### 3.4 `DataTemplate` 里拿不到页面级 ViewModel

WinUI 3 的 `DataTemplate` **不支持** WPF 那种
`{Binding DataContext.X, RelativeSource={RelativeSource Mode=TemplatedParent}}`。
写在 XAML 里编译能过、运行时静默无效。

**修法**：卡片按钮走 `Click` + `Tag`，由 code-behind 转交 `ViewModel.InstallCommand.Execute(item)`。

## 5. 设计说明：为什么把驱动信息收敛成一份 JSON

上游把同一份信息散在三处：

| 位置 | 内容 |
|---|---|
| `installer/driver-manifest.json` | 机器可读的版本 / SHA-256 / productCode |
| `installer/ApexSenseBridge.iss` | `#define` 又写一遍版本号与 productCode |
| `installer/install-usbip.ps1` | 再硬编码一遍版本号与 SHA-256 |

改一次版本要同时改三处，漏一处就会出现「校验通过但装错版本」这类难查的问题。
**DIA 收敛为 `Core/Data/driver-manifest.json` 单一真源**，并补上了上游没有的
`installArgs` / `logArgTemplate`（原先埋在 PS 脚本里）。
