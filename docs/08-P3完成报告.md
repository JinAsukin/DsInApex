## 3. 本轮关键发现

### 3.1 ✅ 跨应用共享缓存验证成功（重要）

`%LOCALAPPDATA%\ApexSenseBridge\learned_executables.json` 里存在一条**官方版早先写入**的记录：

```json
{ "path": "G:\\ACE.COMBAT.8...\\GBTGAME.D.v3.0.14.exe",
  "gameTitle": "Ace Combat 8: Wings of Theve", "steamAppId": 2288340,
  "detectionMethod": "folder name 'ACE.COMBAT.8.WINGS.OF.THEVE'", "successfulSessions": 1 }
```

DIA 启动后**成功读出并显示**（自检「学习记录条数 = 1」）。
→ 证明「文件名 / 路径 / JSON schema 一字不改」的策略是对的，DIA 与官方版可无缝互操作。

### 3.2 ⚠️ WMI 在当前环境**拒绝访问**，靠轮询兜底（预期行为，非缺陷）

```
WMI StartWatcher unavailable: 拒绝访问
WMI StopWatcher unavailable: 拒绝访问
```

`Win32_ProcessStartTrace` / `ProcessStopTrace` 需要**管理员权限**；DIA 以普通用户运行时拿不到。

- 上游同样如此，且**上游本就设计了 250ms 轮询兜底** → 检测能力不受影响，只是「进程一启动就感知」的即时性略降。
- 若用户以管理员身份运行（或安装器提权启动），WMI 生效，检测更即时。
- **这解释了为什么 §5 的「进程一启动就触发」在普通权限下仍需真机复测。**

### 3.3 ⚠️ 上游把「游戏库」与「学习记录」塞在同一个窗口的两个 tab

上游 `GameListWindow` 用 `NavTabCertified` / `NavTabLearned` 在**一个窗口内**切两个视图。
DIA 依 P1 已定的 **8 页导航**结构拆成两页（`GameLibraryPage` / `LearnedPage`）——这是刻意改进，
不是遗漏。副作用：上游的 `initialTab` 参数（从托盘直接打开学习记录 tab）在 DIA 侧对应「导航到学习记录页」。

## 4. 技术决策与取舍

| 决策 | 理由 |
|---|---|
| 游戏库页**不逐行翻译**上游 XAML | 上游含 19 Trigger + 2 MultiTrigger + 20 ControlTemplate；翻译 WPF 模板是纯消耗。改按信息架构用 WinUI 原生控件 + `x:Bind` 重写 |
| 学习记录用 **ListView** 而非 Toolkit DataGrid | 避免为一张表引入额外依赖；ListView + 行模板已满足多选 / 行内删除 |
| 排序只做「名称 / Steam AppID」 | 上游 `GetAllGames()` 返回前已按标题排序，**原始加入顺序不可得**，故「按添加时间」无数据支撑，未实现 |
| VM 不碰 UI | 确认对话框 / 文件选择器留在 code-behind（需 `XamlRoot` / HWND），VM 保持可测 |
| `IsExcluded` 双向绑定时**抑制初始化回写** | 否则加载 215 条时会把读到的值原样重写 215 次盘 |

## 8. 数据源迁移到自有仓库（2026-10-03 追加）

### 8.1 做了什么

游戏库云同步从上游 `ReynArts/ApexSenseBridge` 迁到自有公开仓库
**[`JinAsukin/DsInApex`](https://github.com/JinAsukin/DsInApex)**。

- 本阶段**只放数据**，源码待首个版本交付后再开源过去（GPL-3.0-or-later 的开源义务留到 P7 一并履行）。
- 仓库内容：`data/supported_games.json`（215 款，87 KB）+ `README.md`（用途说明）。
- **公开是硬要求**：raw.githubusercontent / jsDelivr 对私有仓库不支持匿名取用；
  设成私有，客户端拿不到数据（会静默回落到嵌入资源）。

### 8.2 代码变更

`Core/Services/CloudGameListService.FetchLatestFromCloudAsync()` 的 endpoint 列表：

```csharp
string[] endpoints =
[
    "https://cdn.jsdelivr.net/gh/JinAsukin/DsInApex@main/data/supported_games.json",
    "https://raw.githubusercontent.com/JinAsukin/DsInApex/main/data/supported_games.json",
];
```

**顺序是刻意颠倒过的：jsDelivr 在前。** 依据（2026-10-03 实测）：

| 通路 | 结果 |
|---|---|
| `cdn.jsdelivr.net` 直连 | **200** |
| `raw.githubusercontent.com` 直连 | **000（不可达）** |
| `raw.githubusercontent.com` 经代理 | 200 |

`HttpClient` 超时 10 秒，把不可达的排第一 = 每次同步白等 10 秒。
该方法本身是「逐个 endpoint 试、成功即止」，**顺序直接决定同步耗时**。

### 8.3 端到端验证（不是只看 curl）

用临时程序走完整链路（下载 → JSON 解析 → 建索引）：

```
loaded_initial   = 215        (本地缓存)
cloud_sync_ok    = True       ← 从自有仓库同步成功
total_games      = 215
last_updated     = 2026/10/3 10:14:17
probe_acecombat8 = True / Ace Combat 8: Wings of Theve / appid=2288340
cache_written    = True
```

三个地址均返回 **84588 B**（内容完整）。比本地文件 87160 B 少 2572 B，
是 Git 将 CRLF 归一化为 LF 所致 —— **对 JSON 语义无影响**。
