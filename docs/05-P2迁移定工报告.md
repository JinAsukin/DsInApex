## 三、IPC 协议对照表（核心资产）

> 这是整个迁移**唯一可能致命**的部分：C# 端创建命名对象并启动引擎，
> 引擎（C++，**保持上游原样不可改**）打开这些对象并回报状态。
> 任何一处字符串或字节偏移不一致，结果都是"引擎启动了但没有反应"——极难排查。

### 3.1 命名对象

C++ 侧实现（`src/platform/SessionControl.cpp`）：

```cpp
std::string objectName(std::string_view token, std::string_view suffix) {
    std::string result = "Local\\ApexSenseBridge.Session.";
    result.append(token);
    result.push_back('.');
    result.append(suffix);
    return result;
}
```

| 用途 | 对象名 | C# 端创建方式 |
|---|---|---|
| 就绪信号 | `Local\ApexSenseBridge.Session.<token>.Ready` | `EventWaitHandle(false, ManualReset, …)` |
| 停止信号 | `Local\ApexSenseBridge.Session.<token>.Stop` | 同上 |
| 状态块 | `Local\ApexSenseBridge.Session.<token>.Status` | `MemoryMappedFile.CreateNew(…, 512)` |

`token` 由 C# 生成：`Guid.NewGuid().ToString("N")`。
C++ 侧校验 `isValidSessionToken`：**长度必须是 32，字符必须落在 `[0-9a-fA-F]`**。

### 3.2 状态块布局（**512 字节，逐字段对齐**）

C++ 定义（`src/platform/SessionControl.h`）：

```cpp
inline constexpr std::uint32_t kSessionStatusMagic    = 0x53425341; // "ASBS"
inline constexpr std::uint16_t kSessionProtocolVersion = 1;
inline constexpr std::size_t   kSessionStatusSize      = 512;
inline constexpr std::size_t   kSessionMessageCapacity = 496;

enum class SessionPhase : std::uint16_t {
    Empty = 0, Starting = 1, Ready = 2, Stopping = 3, Stopped = 4, Failed = 5,
};

struct SessionStatusBlock {
    std::uint32_t magic;           // @0
    std::uint16_t protocolVersion; // @4
    std::uint16_t phase;           // @6
    std::int32_t  exitCode;        // @8
    std::uint32_t messageLength;   // @12
    std::array<char, 496> message; // @16  (UTF-8)
};
static_assert(sizeof(SessionStatusBlock) == 512);
```

C# 侧读取（上游写法，**保持手写偏移**，勿改用结构体 marshal —— 手写更直观且不怕对齐差异）：

```csharp
var magic   = view.ReadUInt32(0);
var version = view.ReadUInt16(4);
var phase   = (SessionPhase)view.ReadUInt16(6);
var exitCode= view.ReadInt32(8);
var len     = Math.Min(view.ReadUInt32(12), 495u);
var bytes   = new byte[len];
view.ReadArray(16, bytes, 0, bytes.Length);
var message = Encoding.UTF8.GetString(bytes);
```

### 3.3 引擎命令行契约

## 七、关键设计决策（提请在 P2 执行时遵守）

1. **`BridgeSession` 保持"哑进程管理 + IPC"定位，不掺业务。**
   上游这个分层是对的：`BridgeSession` 只管起停与状态，
   `EngineSessionManager` 管业务状态与事件。迁移时不要合并。

2. **手写字节偏移，不改成结构体 marshal。**
   跨语言二进制布局，手写偏移的失败模式（读错值）比 marshal 的失败模式（静默错位）更易发现。

3. **引擎路径优先级：环境变量 > 安装布局 > 开发布局 > 同目录。**
   环境变量 `DSINAPEX_ENGINE_PATH` 是 Spike 期就有的调试开关，保留它可以让
   P2 联调时把引擎指到 `vendor/portable-0.6.3/`，不必先跑安装器。

4. **`stopEvent.Set()` + `WaitForExit` 是正常停止路径，`Kill` 是最后手段。**
   引擎需要走它的 neutralize / restore 流程把手柄还原（`apex_original_restored=yes` 是 P8 验收硬指标）。
   上游给的是 15 秒等待，**不要为了快而改小**。

5. **会话互斥名沿用上游**：`Local\ApexSenseBridge.ActiveSession.Owner.v1`。
   这样 DIA 与 Playnite 插件、以及官方版托盘之间**能互相感知**，不会抢手柄。
