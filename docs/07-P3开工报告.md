## 3. 红线与「必须保持原样」的契约

| 项 | 约束 |
|---|---|
| `%LOCALAPPDATA%\ApexSenseBridge\learned_executables.json` | **文件名、路径、JSON schema（`version:1` + `bindings[]`）一字不改** —— 要与官方版共用同一份学习缓存 |
| `supported_games.json` 云端 URL | 暂沿用上游两个 endpoint（GitHub raw + jsDelivr）；是否改指 DIA 仓库 → **待用户确认**（见 §6） |
| 日志文件名 | `tray_detection.log`（检测+学习）、`tray_crash.log`（异常）**保持不变** |
| 进程白名单 | `PlatformClientProcessFilter` 的启动器黑名单**照搬**，否则会把 Steam/Epic 启动器误判成游戏 |
| 引擎不改 | `ProcessMonitorService` 只调用 `EngineSessionManager`，不碰 C++ |

## 4. P3 工作量定工（GameListWindow.xaml 实测）

| 元素 | 数量 | WinUI 3 替代 |
|---|---|---|
| `<Trigger>` | **19** | `VisualStateManager` |
| `<MultiTrigger>` + `<Condition>` | **2 + 2** | ⚠️ 交叉状态（如「未选中且悬停」），VSM 单维表达不了，需逐处人工判断 |
| **自定义 `<ControlTemplate>`** | **20** | ⚠️ **比 Trigger 更麻烦**：WPF `ControlTemplate` 的 `TargetType`/`TemplateBinding`/`ContentPresenter` 写法与 WinUI 3 有差异，需逐个审查 |
| `<DockPanel>` | 6 | `Grid` + 行列定义 |
| `<WrapPanel>` | 2 | `ItemsWrapGrid` / 手写 |
| `DropShadowEffect` | 2 | `ThemeShadow` |
| `<Style>` / `x:Key` | 11 / 10 | 保留 `Style`（WinUI 支持），`{DynamicResource}` 全换 `loc:Localize` |

**结论**：游戏库页不是「照抄 XAML」，而是**按上游的信息架构重新实现一遍**。
建议直接用 WinUI 3 原生控件 + VSM 重写卡片布局，**不要逐行翻译 WPF 模板**。
